# unbgroup.uz

Статический сайт UNB Group. Деплоится как есть — сборка нужна только для презентаций.

## Структура

```
index.html              главная страница (русская версия и шаблон для остальных)
en/ uz/ zh/             ГЕНЕРИРУЕТСЯ: языковые копии главной и презентаций-страниц
deck.html               просмотрщик презентаций (?d=<презентация>&l=<язык>#<слайд>)
decks/<презентация>/    презентации-страницы: index.html (ru), i18n.js, foto/
css/style.css           стили сайта
css/deck.css            стили просмотрщика
css/deck-page.css       шапка презентаций-страниц
css/deck-theme.css      палитра и шрифты сайта поверх вёрстки презентаций
js/i18n.js              переводы сайта (ru / en / uz / ch)
js/script.js            логика главной страницы
js/deck.js              логика просмотрщика
js/decks-index.js       ГЕНЕРИРУЕТСЯ: какие презентации собраны и по каким адресам
assets/presentations/   исходники презентаций (только вход сборки, не деплоятся)
assets/decks/           ГЕНЕРИРУЕТСЯ: слайды в WebP + deck.js на каждую презентацию
robots.txt              ГЕНЕРИРУЕТСЯ
sitemap.xml             ГЕНЕРИРУЕТСЯ
tools/build-decks.mjs        сборщик презентаций из PDF
tools/build-deck-pages.mjs   сборщик языковых копий презентаций-страниц
tools/build-pages.mjs        сборщик языковых копий главной
tools/build-sitemap.mjs      сборщик sitemap.xml и robots.txt
tools/strip-marks.mjs        снятие логотипов из PDF перед рендером
tools/mark-patches.mjs       закраска логотипов, впечатанных в картинку слайда
tools/find-marks.mjs         поиск впечатанных логотипов (по шаблонам из tools/marks/)
tools/check-marks.mjs        проверка собранных слайдов + контактный лист
```

## Презентации

Презентаций два вида, и различаются они только тем, откуда взялись слайды.

| Презентация | Откуда | Адрес |
| --- | --- | --- |
| `group`, `solar`, `construction` | отрендерены из PDF | `deck.html?d=solar&l=ru` |
| `city`, `power`, `roads`, `hardware`, `mapping`, `farming` | свёрстаны как страницы | `/decks/city/`, `/en/decks/city/` |

Что где лежит, знает `js/decks-index.js`: у презентаций-страниц там записан
свой адрес полем `page`, у остальных его нет, и ссылка ведёт в просмотрщик.
Карточки направлений, `sitemap.xml` и сам `deck.html` читают этот индекс, так
что руками ссылки нигде не проставляются. Старые адреса вида
`deck.html?d=city` не ломаются — просмотрщик уводит с них на новую страницу.

### Отрендеренные из PDF

Каждая страница PDF заранее отрендерена в WebP трёх размеров
(1600 / 800 / 240 px), а `deck.html` листает их с клавиатуры, свайпом и по
миниатюрам.

Так вышло примерно в 20 раз легче: 933 МБ PDF против 46 МБ WebP, то есть
1.2–3.0 МБ на презентацию вместо 2–100 МБ. Плюс мобильный Chrome не умеет
показывать PDF внутри страницы и подсовывал карточку «нажмите, чтобы
открыть» — с HTML этой проблемы нет.

Скачивания PDF на сайте нет. Оно было убрано вместе с логотипами: логотипы
снимаются при рендере слайдов, а в исходных PDF они остаются, поэтому кнопка
«Скачать PDF» раздавала бы ровно то, что с сайта убрано. Сами PDF лежат в
`assets/presentations/` как вход сборки и внесены в `.gitignore`.

### Свёрстанные страницами

`city`, `power`, `roads`, `hardware`, `mapping` и `farming` пришли не PDF, а вёрсткой: слайды
16:9 идут подряд одной страницей, размеры внутри слайда заданы в `cqw`, поэтому
он масштабируется целиком. Рендерить нечего — страница и есть презентация.

Новая презентация-страница подключается так: каталог `decks/<slug>/` с
`index.html`, `i18n.js` и `foto/`, слаг дописывается в `PAGE_DECKS` и `ORDER`
в `tools/build-decks.mjs`, дальше `node tools/build-decks.mjs --index`
(индекс и `sitemap.xml`) и `npm run build:deck-pages` (языковые копии).
Ссылку проставлять не нужно: карточка направления с таким же `data-product`
на главной подхватит презентацию из индекса.

Каждая лежит в `decks/<презентация>/`:

```
index.html   русская страница; она же шаблон для остальных языков
i18n.js      строки слайдов на ru / en / uz / ch
foto/        фотографии в WebP (1280 px)
```

Текст на слайдах размечен `data-i18n`, как и на главной, а
`tools/build-deck-pages.mjs` раскладывает переводы по копиям `/en/decks/…`,
`/uz/decks/…`, `/zh/decks/…`. Копии генерируются, править их руками нельзя.
Значения словаря — HTML: внутри строк живут `<br>`, `<b>` и `<span>`, без них
слайд рассыпается, поэтому подставляются они разметкой, а не текстом.

Листает страницу `js/deck-page.js` — теми же клавишами, свайпом, стрелками и
миниатюрами, что и `deck.html`, и ссылка вида `/decks/city/#7` так же открывает
нужный слайд. В разметке слайды лежат подряд: без скрипта страница остаётся
читаемой и печатается целиком, а скрипт вешает на `<body>` класс `dp-on` и
показывает по одному. Кнопки листалки лежат в разметке спрятанными, а не
рисуются скриптом, — иначе их подписи прошли бы мимо сборщика переводов.
Миниатюра — копия слайда в узкой коробке: слайды свёрстаны в `cqw`, поэтому
уменьшенная копия собирается сама, отдельных картинок для полосы не нужно.

Русский текст лежит в двух местах сразу — в разметке шаблона и в словаре.
Сборщик сверяет их и падает при расхождении: иначе русская страница и переводы
тихо разъедутся, и заметит это уже посетитель. Правите слайд — правьте обе
стороны.

Шапка (возврат на сайт и переключатель языков) добавлена к вёрстке слайдов и
живёт в `css/deck-page.css`; её строки берутся из общего `js/i18n.js`.

Каждая презентация свёрстана отдельно и со своей палитрой, поэтому поверх её
`<style>` подключается `css/deck-theme.css` — он идёт последним и переопределяет
оформление: переназначает цветовые переменные слайдов (`--navy`, `--cyan`,
`--orange` и прочие) на палитру сайта, ставит те же шрифты (Space Grotesk /
IBM Plex Sans / IBM Plex Mono) и подтягивает рамки, скругления и заливки.
Сетки и размеры в `cqw` он не трогает — вёрстка слайдов остаётся авторской.
Отсюда и порядок в `<head>`: сначала шрифты и `deck-page.css`, потом `<style>`
презентации, и только затем `deck-theme.css`.

Исходники, из которых страницы собраны — вёрстка и фотографии до сжатия, — в
`assets/presentations/html/` вместе с PDF остальных презентаций.

### Логотипы

Со слайдов убраны оба бренда — и Drone Service, и UNB Group. В интерфейсе сайта
логотип UNB остаётся: в шапке просмотрщика, на главной и в favicon.

Ниже — про презентации из PDF. У свёрстанных страницами снимать нечего:
логотипов в вёрстке нет, файлы логотипов из исходников на сайт не переносились.

Логотипы лежали в PDF отдельными объектами, поэтому они выключаются, а не
закрашиваются: под ними проступает настоящая подложка. Заодно снимаются плашки
и рамки, которые рисовались под логотипом векторно, иначе от них остались бы
пустые прямоугольники.

Логика в `tools/strip-marks.mjs`, опознание — по SHA1 пикселей. Хеши двух брендов
лежат там же двумя списками: `DRONE_SERVICE_HASHES` и `UNB_HASHES`. Списки
раздельные не ради разной обработки — гасятся они одинаково — а потому что
проверяются по-разному.

Часть слайдов экспортирована единой плоской картинкой с уже впечатанным
логотипом: выключать нечего, область закрашивается. Такие места перечислены
в `tools/mark-patches.mjs` (закраска отрендеренного слайда) и в
`FLATTENED_PATCHES` внутри `strip-marks.mjs` (закраска картинки до рендера —
нужна там, где поверх метки нарисовано что-то ещё).

Проверка результата:

```bash
node tools/check-marks.mjs
```

Скрипт сканирует все собранные слайды на фирменный зелёный Drone Service и падает,
если нашлось что-то новое, складывая подозрительные слайды в `tools/.check/`.

Семь слайдов зелёные по делу — карта инсоляции, рельефная карта, рамки карточек
дефектов, стрелка «Умный город». Они перечислены в `REVIEWED` внутри скрипта и
не роняют проверку; порог не занижался, иначе начали бы теряться мелкие логотипы.

Для UNB такой проверки нет: логотип чёрный, а под «чёрное на светлом» подходит
почти весь текст слайдов — любой порог, который ловит метку, ловит и заголовки.
Поэтому скрипт пишет `tools/.check/sheet.html` — контактный лист всех слайдов;
UNB проверяется глазами по нему. Для Drone Service лист тоже не лишний: цвет
ловит не всё, в одной презентации логотип был серым.

### Пересборка

Нужна при добавлении или замене PDF в `assets/presentations/`.

```bash
npm install                            # один раз: mupdf + sharp
npm run build:decks                    # все презентации
node tools/build-decks.mjs solar-ru    # только одна
```

Сборщик сам обновляет `js/decks-index.js`, поэтому список доступных
презентаций и языков в коде править не нужно — карточки направлений и
переключатель языков читают его на лету.

Имена файлов задают, что куда попадёт:

| PDF | Презентация |
| --- | --- |
| `assets/presentations/UNB_Group_RU.pdf` | `deck.html?d=group&l=ru` |
| `assets/presentations/products/solar-ru.pdf` | `deck.html?d=solar&l=ru` |

Языки: `ru`, `en`, `uz`, `ch`. Если презентации на выбранном языке нет,
показывается русская версия, а интерфейс остаётся на языке посетителя.
Названия презентаций живут в `TITLES` внутри `tools/build-decks.mjs`.

Презентации-страницы рендерить не нужно, им хватает своей сборки:

```bash
npm run build:deck-pages               # копии /en/decks/…, /uz/…, /zh/…
node tools/build-deck-pages.mjs city   # только одна презентация
node tools/build-decks.mjs --index     # переписать js/decks-index.js, ничего не рендеря
```

`--index` нужен, когда у презентации-страницы изменилось число слайдов или
название: пересобирать ради этого PDF остальных презентаций незачем.

## Языковые версии главной

У каждого языка свой адрес: `/` (ru), `/en/`, `/uz/`, `/zh/`. Переключатель —
обычные ссылки, а не JS: иначе поисковик не находит переводы и индексирует
только русскую версию.

`index.html` — единственный источник правды. Каталоги `en/`, `uz/`, `zh/`
**генерируются, править их руками нельзя** — следующая сборка затрёт правки.

```bash
npm run build            # языковые копии + sitemap.xml + robots.txt
npm run build:pages      # только копии
npm run build:sitemap    # только sitemap.xml и robots.txt
```

Прогонять после любой правки `index.html` или `js/i18n.js`. Тексты берутся
из `js/i18n.js` по атрибутам `data-i18n`, так что новый блок на главной
достаточно разметить ключом — перевод подхватится сам. Заголовок вкладки и
`description` живут в ключах `meta.title` и `meta.description`.

Публичный код китайского — `zh` (каталог и `hreflang`), внутренний в словаре
и в URL презентаций остаётся `ch`; Google понимает только `zh`.

## Локальный запуск

Любой статический сервер из корня репозитория, например:

```bash
npx serve .
```

Открыть `index.html` или `deck.html` двойным щелчком (через `file://`) тоже
можно — данные презентаций подгружаются обычным `<script>`, а не `fetch()`,
как раз чтобы это работало без сервера.
